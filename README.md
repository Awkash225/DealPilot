# DealPilot

DealPilot is an AI-assisted shopping comparison demo. It helps a buyer turn a shopping mission and budget into a shortlist of illustrative sample offers, compare offer eligibility, and optionally try a PayPal Sandbox checkout.

> **Hackathon prototype:** sample sellers and offers are illustrative. PayPal Sandbox transactions are test transactions. No actual sample seller receives a payout, and this application does not implement marketplace payouts or escrow.

## Problem

Comparing product listings can take time, and buyers can overlook a must-have requirement or spend beyond their budget. DealPilot demonstrates a flow that makes those requirements and the price ceiling visible before a buyer chooses whether to continue.

## Product overview

Enter a shopping mission and maximum budget. DealPilot analyzes the request, compares the existing sample offer catalog against mandatory requirements and budget, and shows an eligible recommendation when one exists. The buyer can then open a simulated negotiation suggestion or choose to continue to a Sandbox payment for the offer’s **listed price**.

The suggested counteroffer is hypothetical. No seller has accepted it, and it is never used as the PayPal payment amount.

## Features

- Gemini structured analysis with server-side response validation.
- Model fallback and bounded retry for transient Gemini errors.
- Clearly distinguished deterministic demo analysis when Gemini is unavailable.
- Server-side mandatory requirement, offer eligibility, and budget checks.
- Existing illustrative sample offers only; the browser and AI do not set their prices.
- PayPal Sandbox order creation and capture after buyer approval.
- Listed price and currency shown before checkout.
- Payment success, pending, cancellation, and failure feedback.

## How Gemini analysis works

The server sends the shopping mission, buyer budget, and trusted sample offer facts to Gemini using structured JSON output. DealPilot validates the response, then independently applies the trusted offer catalog, detected mandatory requirements, and buyer’s budget before selecting an eligible offer.

The analysis attempts these models in order:

1. `gemini-3.8-flash`
2. `gemini-3.5-flash-lite`
3. `gemini-3.1-flash-lite`

Transient `429`, `503`, and `504` failures receive a bounded number of retries with exponential backoff and jitter. If Gemini remains unavailable, DealPilot returns a **deterministic demo analysis** and labels it “Demo analysis — AI temporarily unavailable.” That result is not generated by Gemini.

## How PayPal Sandbox checkout works

The browser loads PayPal’s JavaScript SDK v6 from the Sandbox host. When the buyer chooses the PayPal button, the server creates an Orders v2 order using the selected eligible sample offer’s trusted listed price in USD. The browser never supplies the amount.

After the buyer approves the order with PayPal, the server retrieves and verifies the order before requesting capture. It checks the actual capture response and reports completed or pending status. The configured Sandbox REST app’s merchant receives a test transaction; **no illustrative sample seller receives payment**.

## Architecture and technology

- Next.js 16 App Router and React 19.
- TypeScript.
- Gemini API through `@google/genai`.
- PayPal Orders v2 REST API from server-only routes.
- PayPal JavaScript SDK v6 for buyer approval.
- Trusted sample offer catalog in `lib/offers.ts`.
- Short-lived HMAC-signed checkout eligibility tokens and deterministic PayPal request IDs, verified against the trusted offer catalog on every server request.

Key routes and files:

- `app/api/analyze/route.ts` — Gemini analysis, fallback, and server-side offer eligibility.
- `app/api/paypal/orders/route.ts` — Sandbox order creation.
- `app/api/paypal/capture/route.ts` — order verification and capture.
- `lib/paypal-rest.ts` — Sandbox OAuth and REST requests.
- `app/paypal-checkout.tsx` — JavaScript SDK button and buyer payment states.

## Requirements

- Node.js 20.9 or newer.
- npm.
- Gemini API credentials for AI-generated analysis. Without a Gemini key, deterministic analysis remains available.
- PayPal Sandbox REST app credentials to use Sandbox checkout.

## Install

From the application and Git repository root (`E:\DealPilot\web`):

```powershell
npm.cmd ci
Copy-Item .env.example .env.local
```

Edit `.env.local` locally and fill in the credentials described below. `.env.local` is ignored by Git. Never commit it or paste its contents into logs, issues, or chat.

## Environment variables

| Variable | Use | Exposure |
| --- | --- | --- |
| `GEMINI_API_KEY` | Gemini server API access | Server only |
| `PAYPAL_CLIENT_ID` | PayPal Sandbox OAuth app ID | Server only |
| `PAYPAL_CLIENT_SECRET` | PayPal Sandbox OAuth secret | Server only |
| `NEXT_PUBLIC_PAYPAL_CLIENT_ID` | Same Sandbox app ID for the browser JavaScript SDK | Public by design |

Create a Gemini API key and a PayPal Developer Sandbox REST app. Use the Sandbox app’s client ID for both PayPal client ID variables and its secret for `PAYPAL_CLIENT_SECRET`. Keep the secret server-side. The backend is pinned to `https://api-m.sandbox.paypal.com`; this project does not use PayPal Live endpoints.

`.env.example` contains placeholders only. Replace the placeholders in your private local environment; do not put real credentials in `.env.example`.

## Run locally

```powershell
npm.cmd run dev
```

Open <http://localhost:3000>.

## PayPal Sandbox testing

1. Configure all three PayPal variables with the same Sandbox REST app credentials.
2. Start the app and analyze a mission that has an eligible sample offer within budget.
3. Confirm the listed price shown in the approval card is the amount displayed for checkout.
4. Use a PayPal Sandbox personal account to approve or cancel the transaction.
5. Confirm the resulting capture in the Sandbox business account associated with the configured REST app. The account may not be the business account you expect if credentials came from a different Sandbox app.
6. Exercise approval, cancellation, successful capture, pending capture, and failure paths.

No live Sandbox transaction was verified as part of repository setup. A successful build is not proof of a successful PayPal transaction.

## Demo limitations and seller disclosure

- Sample sellers, product details, and listed prices are illustrative demo data, not live listings or seller commitments.
- No sample seller has accepted a counteroffer or receives a payout from this app.
- PayPal Sandbox payments are test transactions and go to the Sandbox merchant associated with the configured REST app.
- There is no marketplace payout, escrow, shipping workflow, or real purchase fulfillment.
- Checkout eligibility is a two-hour HMAC-signed token using the existing server-only `PAYPAL_CLIENT_SECRET`. Server routes independently recheck offer requirements, eligibility, budget, order amount, and currency. Deterministic PayPal request IDs and PayPal order reads support retries across serverless instances. The app has no durable order ledger or buyer identity; expired tokens require a fresh analysis. This remains a hackathon prototype, not a production marketplace payment system.
- Gemini can be unavailable; after model request attempts fail, deterministic demo analysis is labeled separately. Malformed or incomplete Gemini output is rejected by response validation.

## Security considerations

- Keep `GEMINI_API_KEY` and `PAYPAL_CLIENT_SECRET` out of browser code and source control.
- `.env.local` is excluded by `.gitignore`; verify it remains untracked before publishing.
- Use only Sandbox PayPal credentials with this prototype. The server uses a fixed Sandbox REST host.
- Order amounts and offer details come from the server’s trusted sample catalog, not browser or AI payment fields.
- The server checks offer eligibility, budget, order status, amount, currency, and capture response before reporting success.
- PayPal idempotency is provided for order creation and capture using deterministic request IDs; the application itself has no durable transaction ledger, buyer identity, or marketplace payout controls.
- Sandbox payments are not seller payments. Never represent a demo analysis or test transaction as a real seller match or fulfillment.
